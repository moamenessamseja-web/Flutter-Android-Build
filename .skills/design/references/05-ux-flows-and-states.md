# UX Flows and States

For each critical flow document trigger, inputs, validation, progress/disabled state, success outcome, failure/recovery, persistence, and cancellation.

Every meaningful action needs understandable feedback: saved locally vs synced; estimated vs measured; pending vs complete; permission unavailable vs feature broken. Never show success before the operation succeeds.

Consider only states real to the product: first-use/empty, populated, many records, stale/incomplete data, loading if applicable, recoverable error, offline, permission denied, disabled action, destructive confirmation, large font, and long localized strings.

Distinguish source values from derived values and estimates. Show comparison basis/period. Do not imply unsupported precision. Handle resets, replacements, missing history, and invalid sequences where domain-relevant. Use semantics, visible focus, sufficient touch targets, readable contrast, non-color cues, and chart alternatives.
